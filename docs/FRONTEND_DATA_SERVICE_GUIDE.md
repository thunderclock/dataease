# DataEase 数据服务前端使用指南

## 概述

本文档介绍如何在 DataEase 前端界面中使用数据服务功能，包括如何配置 AccessKey、测试查询接口、使用数据集参数等。

## 功能入口

数据服务功能位于图表编辑界面，通过以下方式打开：

1. 在图表编辑界面，点击工具栏中的"数据服务"按钮
2. 或者通过右键菜单选择"数据服务"

## 界面说明

数据服务对话框包含以下标签页：

### 1. AccessKey 配置

用于配置 AccessKey 和 AccessSecret，用于 API 调用的签名验证。

**配置步骤**：
1. 在"AccessKey"输入框中输入您的 AccessKey
2. 在"AccessSecret"输入框中输入您的 AccessSecret（输入时会隐藏显示）
3. 配置完成后，在测试查询时会自动使用这些凭证进行签名

**注意事项**：
- AccessKey 和 AccessSecret 需要从 DataEase 系统的"AccessKey 管理"页面获取
- AccessSecret 只在生成时显示一次，请妥善保存
- 配置的 AccessKey 信息仅用于当前会话的测试，不会保存到服务器

### 2. 查询图表数据（queryChartData）

使用图表字段 ID 查询数据，适用于从已有图表配置中获取数据。

#### 配置子标签页

**数据集ID**：
- 输入数据集ID（tableId）
- 系统会自动从当前图表配置中获取

**维度字段**：
- 从可用字段列表中选择维度字段
- 支持多选
- 字段会自动从图表配置中加载

**指标字段**：
- 从可用字段列表中选择指标字段
- 支持多选
- 字段会自动从图表配置中加载

**过滤条件**：
- 点击"添加过滤条件"按钮添加过滤条件
- 每个过滤条件包含：字段ID、操作符、值
- 可以添加多个过滤条件

**分页信息**：
- 当前页码（从1开始）
- 每页大小（1-10000）

#### 调试子标签页

**功能**：
- **测试查询**：发送请求并查看响应结果
- **格式化请求**：格式化 JSON 请求体，便于阅读
- **复制请求**：复制请求 JSON 到剪贴板

**显示内容**：
- **请求**：显示发送的请求 JSON
- **响应**：显示服务器返回的响应 JSON
- **结果数据**：以表格形式显示查询结果，包括：
  - 数据表格（列和行）
  - 总记录数
  - 总页数
  - 当前页码

#### 保存子标签页

**功能**：
- 保存当前配置为服务模板
- 加载已保存的服务模板
- 删除已保存的服务模板

**操作步骤**：
1. 填写服务名称和描述
2. 点击"保存服务"按钮
3. 服务会保存到浏览器本地存储中

### 3. 查询数据（queryData）

使用字段名查询数据，适用于直接通过字段名进行查询的场景。

#### 配置子标签页

**数据集ID**：
- 自动从图表配置中获取
- 显示为只读状态

**维度字段**：
- 自动从图表配置中解析
- 以标签形式显示，不可编辑

**指标字段**：
- 自动从图表配置中解析
- 以标签形式显示，不可编辑

**过滤条件**：
- 使用可视化过滤器编辑器
- 支持复杂的嵌套过滤条件
- 支持相对时间过滤

**数据集参数**：
- **重要功能**：用于替换 SQL 查询中的参数变量
- 点击"添加数据集参数"按钮添加参数
- 每个参数包含：
  - **变量名**：SQL 中定义的变量名（如：`start_date`）
  - **操作符**：`eq`（等于）、`in`（包含）、`between`（区间）
  - **参数值**：参数值，多个值用逗号分隔

**数据集参数使用说明**：
1. **变量名**：必须与 SQL 查询中定义的变量名完全一致（不包含 `${}` 符号）
   - 例如：SQL 中定义 `${start_date}`，变量名应填写 `start_date`
2. **操作符**：
   - `eq`：等于，用于单个值匹配
   - `in`：包含，用于多个值匹配（参数值用逗号分隔）
   - `between`：区间，用于范围匹配（参数值填写两个值，用逗号分隔）
3. **参数值**：
   - 单个值：直接填写，如 `2024-01-01`
   - 多个值：用逗号分隔，如 `active,pending,completed`
   - 区间值：用逗号分隔两个值，如 `2024-01-01,2024-12-31`
4. **注意事项**：
   - `datasetTableId` 和 `datasetGroupId` **不需要填写**，后端会自动从 `tableId` 获取
   - 参数值会替换 SQL 查询中对应的变量
   - 如果 SQL 中定义了参数变量但未传入参数值，查询可能会失败

**数据集参数示例**：

假设 SQL 查询为：
```sql
SELECT * FROM orders 
WHERE order_date >= ${start_date} 
  AND order_date <= ${end_date}
  AND status IN (${status_list})
```

对应的参数配置：
- 参数1：
  - 变量名：`start_date`
  - 操作符：`eq`
  - 参数值：`2024-01-01`
- 参数2：
  - 变量名：`end_date`
  - 操作符：`eq`
  - 参数值：`2024-12-31`
- 参数3：
  - 变量名：`status_list`
  - 操作符：`in`
  - 参数值：`active,pending,completed`

**分页信息**：
- 当前页码（从1开始）
- 每页大小（1-10000）

#### 调试子标签页

功能与"查询图表数据"的调试子标签页相同。

#### 保存子标签页

功能与"查询图表数据"的保存子标签页相同。

## 使用流程

### 基本查询流程

1. **打开数据服务对话框**
   - 在图表编辑界面点击"数据服务"按钮

2. **配置 AccessKey**（可选，用于 API 签名验证）
   - 切换到"AccessKey 配置"标签页
   - 输入 AccessKey 和 AccessSecret

3. **选择查询方式**
   - **查询图表数据**：使用图表字段 ID，适合从已有图表配置获取数据
   - **查询数据**：使用字段名，适合直接通过字段名查询

4. **配置查询参数**
   - 选择数据集
   - 选择维度和指标字段
   - 配置过滤条件（可选）
   - 配置数据集参数（可选，仅 queryData 支持）
   - 设置分页信息

5. **测试查询**
   - 切换到"调试"子标签页
   - 点击"测试查询"按钮
   - 查看请求和响应 JSON
   - 查看结果数据表格

6. **保存配置**（可选）
   - 切换到"保存"子标签页
   - 填写服务名称和描述
   - 点击"保存服务"按钮

### 使用数据集参数流程

1. **确认 SQL 查询中的参数变量**
   - 在数据集编辑界面查看 SQL 查询
   - 找到形如 `${variable_name}` 的参数变量

2. **配置数据集参数**
   - 切换到"查询数据"标签页
   - 在"数据集参数"部分点击"添加数据集参数"
   - 填写变量名（不包含 `${}` 符号）
   - 选择操作符
   - 填写参数值

3. **测试查询**
   - 切换到"调试"子标签页
   - 点击"测试查询"按钮
   - 检查请求 JSON 中的 `params` 字段是否正确
   - 查看查询结果是否符合预期

## 常见问题

### 1. 数据集参数没有生效

**可能原因**：
- 变量名与 SQL 中的变量名不一致
- 参数值格式不正确
- SQL 查询中没有定义对应的参数变量

**解决方案**：
- 检查变量名是否与 SQL 中完全一致（区分大小写）
- 确认参数值格式正确（多个值用逗号分隔）
- 检查 SQL 查询中是否定义了对应的参数变量

### 2. 查询返回空结果

**可能原因**：
- 过滤条件过于严格
- 数据集参数值不匹配
- 字段选择错误

**解决方案**：
- 检查过滤条件是否合理
- 检查数据集参数值是否正确
- 确认选择的字段存在于数据集中

### 3. AccessKey 签名验证失败

**可能原因**：
- AccessKey 或 AccessSecret 不正确
- 时间戳过期（超过5分钟）

**解决方案**：
- 检查 AccessKey 和 AccessSecret 是否正确
- 重新配置 AccessKey 信息
- 确保系统时间正确

### 4. 参数值格式问题

**数据集参数值格式要求**：
- 单个值：直接填写，如 `2024-01-01`
- 多个值（in 操作符）：用逗号分隔，如 `value1,value2,value3`
- 区间值（between 操作符）：用逗号分隔两个值，如 `2024-01-01,2024-12-31`

**注意事项**：
- 不要包含空格（除非值本身需要空格）
- 日期格式要与数据库中的格式一致
- 字符串值不需要加引号

## 最佳实践

### 1. 参数命名规范

- 使用有意义的变量名，如 `start_date`、`end_date`、`status` 等
- 避免使用特殊字符
- 使用下划线分隔单词

### 2. 参数值管理

- 对于常用的参数值，可以保存为服务模板
- 定期检查参数值是否仍然有效
- 对于日期参数，使用标准的日期格式（如 `YYYY-MM-DD`）

### 3. 测试建议

- 在正式使用前，先在调试界面测试查询
- 检查请求 JSON 确保参数正确传递
- 查看响应 JSON 了解返回的数据结构
- 使用小数据集进行测试，避免查询时间过长

### 4. 性能优化

- 合理使用过滤条件，减少查询数据量
- 使用分页功能，避免一次性查询大量数据
- 对于复杂查询，考虑使用索引字段作为过滤条件

## 技术说明

### 数据集参数自动处理

在 `queryData` 接口中，数据集参数的 `datasetTableId` 和 `datasetGroupId` 字段**不需要在前端传递**，后端会自动处理：

1. **datasetGroupId**：自动设置为请求中的 `tableId`（数据集组ID）
2. **datasetTableId**：自动从数据集组下的第一个数据集表中获取

因此，前端只需要传递：
- `variableName`：参数变量名
- `operator`：操作符（可选，默认为 `eq`）
- `value`：参数值数组

### 参数 ID 构造

后端会自动构造参数 ID，格式为：`{datasetTableId}|DE|{variableName}`

例如：
- datasetTableId: `123456`
- variableName: `start_date`
- 参数 ID: `123456|DE|start_date`

### 参数值处理

前端会将参数值字符串（逗号分隔）转换为数组：
- 输入：`"2024-01-01,2024-12-31"`
- 转换后：`["2024-01-01", "2024-12-31"]`
